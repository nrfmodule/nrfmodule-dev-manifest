# nRFModule v2.4.0 — release notes (DRAFT, 2026-07-28 overnight; not tagged)

Tag core + sdk together as v2.4.0; bump the manifest v2.x pin after. v2.3.0 is
burned (tagged pre-fix-wave).

## Breaking / consumer-visible API changes

- `nrf_modem_at_cmd_datamode()` / `nrf_modem_at_datamode_send()`: data-mode
  send now returns the **byte count** on success (was 0).
- `sm_modem_power_mgmt_txn_begin()` / `txn_end()` / `send_at()` **removed**
  (link break for prebuilt-`libmodem_core.a` consumers — pair core+sdk tags).
  All multi-step exchanges go through `nrf_modem_at_lock()/unlock()`
  (owner-recursive single AT mutex).
- AT lock contention now returns **`-EAGAIN`** (was `-EBUSY`).
- **Config contract**: consumer apps MUST build with a cooperative system
  workqueue (`CONFIG_SYSTEM_WORKQUEUE_PRIORITY < 0`) — enforced by
  BUILD_ASSERT in `sm_at_client.c`.
- Shell: raw `sm <at>` passthrough **removed**; engine-routed `smat <at>`
  replaces it (locking + wake included). Bench scripts must migrate.
  `smsh uart enable/disable` now warn that they bypass power-mgmt state.
  (PR in flight — include only if merged before the tag.)

## New features

- **AT link-dark event** (`nrf_modem_at_link_dark_handler_set()`, sdk #30 /
  core #52): consecutive AT-timeout detector fires an app-policy event at
  `NRFMODULE_AT_TIMEOUT_RECOVERY_THRESHOLD` (default 5), spaced by
  `NRFMODULE_AT_TIMEOUT_RECOVERY_SPACING_S` (default 1800 s, hard floor).
  Optional in-library reset behind `NRFMODULE_AT_TIMEOUT_AUTO_RESET`
  (**default n**). Handler contract: called with the AT lock held — don't
  block; inline `nrf_modem_lib_reset()` permitted (~55 s worst case).
- New Kconfigs: `NRFMODULE_AT_RESYNC_DRAIN_MS` (300), `NRFMODULE_AT_RESYNC_POLL_MS`
  (50), the two recovery knobs above, and `NRFMODULE_AT_TIMEOUT_AUTO_RESET`.

## Fixes

- **RI wake no longer swallows the URC that raised it** (core #49 / #37):
  modem-initiated wake brings DTR/UART up synchronously under the AT lock
  with no AT ping; bounded retry; AWAKE only on hardware evidence.
  HIL: 25/25 park→host-wake→re-park soak cycles, all wake-attempt-1
  (2026-07-27 overnight bench).
- Single-mutex concurrency baseline (core #48 / sdk #29): redirectable
  response accumulator (no sysworkq barrier), atomic command+datamode
  transaction, post-timeout link quarantine, CAS command/response pairing
  (fixes the AT-link-wedge-after-timeout desync, core #22).
- URC dispatch consolidation + drop-safe #XMQTTMSG reassembly (core #47/#23/#26).
- Reset/recovery: `nrf_modem_lib_reset()` suppresses the wake ladder and
  timeout counting for its whole duration; DTR re-cycled for the
  edge-triggered wake (IDLE-with-DTR-high transient).
- If merged before tag (PRs open at draft time): non-PM builds no longer lose
  automatic DTR after a slow modem boot or failed reset (core #51); RI
  interrupt silenced before AT-client teardown (core #50); nrf9151 board def
  synced to the deployed modem-FW UART config (sdk #20); standalone sdk
  west.yml pins NCS v3.2.1 (sdk #21); manifest pins ncs-serial-modem to the
  tested SHA (manifest #8).

## Infrastructure

  retention, quota-proof uploads (manifest #11).
